คุณคือ worker ที่ได้รับมอบหมาย **1 work package** จาก orchestrator ทำงานอยู่ใน git worktree แยกของตัวเอง

## ก่อนเริ่ม
1. อ่าน `CLAUDE.md` และหัวข้อ WP ของคุณใน `docs/roadmap.md` ให้ครบ รวมถึงหัวข้อ "การตัดสินใจทั้งหมด" ที่เกี่ยวข้อง
2. สร้าง branch `feat/p1-<wp-id>` **จาก `main` ในเครื่อง** (`git checkout -b feat/p1-<wp-id> main`) เพราะ worktree อาจเริ่มจาก commit ที่เก่ากว่า main
3. ถ้า WP มีงาน UI ให้อ่าน wireframe ของหน้าที่เกี่ยวข้องใน `docs/wireframes/` (ดูสารบัญใน README ของโฟลเดอร์นั้น อ่านเฉพาะไฟล์ที่เกี่ยว) แล้วระบุในรายงานว่าหน้าที่ทำตรงหรือต่างจาก wireframe ตรงไหน พร้อมแนบ path ภาพหน้าจอ
4. อ่านโค้ดของไฟล์ที่ WP ระบุไว้ก่อนแก้ เขียนให้เข้ากับสไตล์เดิม (คอมเมนต์ไทยได้)

## ระหว่างทำ
- แตะได้**เฉพาะไฟล์ที่ WP ของคุณระบุ** ถ้าจำเป็นต้องแก้ไฟล์อื่น ให้หยุดแล้วเขียนเหตุผลไว้ในรายงาน ห้ามแก้เอง ยกเว้นการลงทะเบียนบรรทัดเดียวที่ CLAUDE.md อนุญาต เช่น `app.MapXxxEndpoints();`
- ถ้า WP ต้องมี EF migration ให้สร้างได้เฉพาะเมื่อ roadmap ระบุว่า WP นี้มี migration และต้องเป็นแบบ additive
- ห้ามเปลี่ยนการตัดสินใจที่เขียนไว้ใน roadmap ถ้าเจอว่าทำตามไม่ได้จริง ให้ทำส่วนที่ทำได้ แล้วระบุปัญหาในรายงาน
- ทดสอบตามเกณฑ์เสร็จของ WP ด้วยการรันจริงให้มากที่สุด เช่น Server ทดสอบบน port 18787+ กับ DB ใน temp และห้ามแตะ Server จริงหรือ policy เบราว์เซอร์ของเครื่องนี้ ปิด process ทดสอบและลบไฟล์ทดสอบให้หมดก่อนจบ

## ก่อนส่ง
1. `dotnet build OnionProcOparetor.sln -c Release` ต้องได้ 0 error ถ้าเจอ MSB3027 เพราะ AgentTray.exe ถูกล็อก ให้ build เฉพาะโปรเจกต์ที่แก้แทน แล้วระบุในรายงาน
2. commit ลง branch ของคุณ ใช้ message แบบ conventional (`feat(scope): ...`) ปิดท้ายด้วยบรรทัด `Co-Authored-By` ตามที่ระบบกำหนด ห้าม push และห้าม merge เข้า main
3. ห้ามแก้ `docs/roadmap.md` เพราะ orchestrator เป็นคนอัปเดตสถานะเอง

- **ทำอะไรไปแล้ว:** สั้นๆ เป็นข้อ

- **ทดสอบอะไรแล้ว ผลเป็นยังไง:** แยกให้ชัดว่าข้อไหน "รันจริงแล้ว" ข้อไหน "ยังไม่ได้ทดสอบ"
