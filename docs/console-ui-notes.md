บันทึกไว้เพื่อกันไม่ให้ของที่ตั้งใจทำถูก "แก้กลับ" ในอนาคต เอกสารนี้ครอบคลุมเฉพาะ
`src/OnionProcOparetor.Console` (WPF) คู่กับ [`onlineconsole-ui-notes.md`](onlineconsole-ui-notes.md)
ที่ครอบคลุมฝั่ง Blazor

เป้าหมายของงานรอบนี้: ให้ Console กับ OnlineConsole **ดูเป็นผลิตภัณฑ์เดียวกัน** ไม่ใช่สองแอปที่บังเอิญ
ต่อเซิร์ฟเวอร์ตัวเดียวกัน โดยไม่ตัดความสามารถของฝั่ง WPF ลงเพื่อให้เท่ากับเว็บ

## 1. กับดักที่ต้องรู้ก่อนแก้ไฟล์ธีม

### 1.1 ห้ามใช้ `{StaticResource}` กับ `Brush.*` / `Color.*` เด็ดขาด

`StaticResource` resolve **ครั้งเดียวตอน parse XAML** ใครใส่ไว้ที่ไหน ธีมตรงนั้นจะค้างอยู่กับธีมแรก
ที่โหลดตลอดไป และจะไม่มีใครสังเกตจนกว่าจะมีคนสลับไปโหมดมืดแล้วเจอกล่องขาวโพลนกล่องเดียวกลางจอ

> **ทุก token สีต้องอ้างด้วย `{DynamicResource}` เสมอ** — ส่วน `Style`/`FontFamily` ใช้
> `StaticResource` ได้ตามปกติ เพราะไม่ได้เปลี่ยนตามธีม

ฝั่ง code-behind ก็เหมือนกัน: `FindResource("Brush.X")` คืน "ค่า ณ ตอนนั้น" ครั้งเดียว ต้องใช้
`SetResourceReference(...)` แทน ซึ่งผูกเป็น DynamicResource จริง

### 1.2 Freezable ที่ประกาศ inline ใน `Style` setter ผูก DynamicResource ไม่ได้

เดิม `ConsoleGridRowStyle` เขียนสี hover เป็น
`<SolidColorBrush Color="{StaticResource Color.Accent.Light}" Opacity="0.15"/>` แบบ inline อยู่ใน
`Setter.Value` — WPF จะ **freeze** brush ตัวนั้น ทำให้ผูก DynamicResource เข้าไปไม่ได้ ธีมจะค้าง
ตอนนี้ย้ายไปเป็น token `Brush.Row.Hover` แล้ว **อย่าเขียน brush inline ใน style setter อีก**

### 1.3 ไฟล์ palette สองไฟล์ต้องมี key ครบเท่ากันเสมอ

`Theme/Colors.Light.xaml` กับ `Theme/Colors.Dark.xaml` ประกาศ `x:Key` ชุดเดียวกันเป๊ะ (ตอนนี้ 70 ตัว)
`ThemeService` สลับทั้ง dictionary ทีเดียว key ที่มีอยู่ไฟล์เดียวจะกลายเป็น DynamicResource ที่หา
ไม่เจอในอีกธีมหนึ่ง ซึ่ง **ไม่ throw** — มันเงียบแล้ววาดเป็นค่าว่าง

`ThemeService.VerifyKeyParity()` เช็คตอน startup ทุกครั้งและเขียนลง `console.log` ถ้าไม่ตรง
**เพิ่ม token เมื่อไหร่ ต้องเพิ่มสองที่**

### 1.4 คอมเมนต์ XML ห้ามมี `--`

เจอตอน build พัง 2 ครั้งในงานรอบนี้: `<!-- --bg -->` (อ้างชื่อ CSS variable) และเส้นคั่น
`<!-- ---------- -->` ผิด XML ทั้งคู่ ในไฟล์ธีมจึงเขียนชื่อ CSS variable เป็น `css:bg` แทน และใช้
`=` เป็นเส้นคั่น

### 1.5 `ThemeMode` ยังจำเป็น แม้จะ template เองเกือบหมดแล้ว

`Application.ThemeMode` / `Window.ThemeMode` (ยัง `[Experimental]` — ต้อง `#pragma warning disable WPF0001`)
คุมคอนโทรลที่เรา **ไม่ได้** re-template เอง: ComboBox, CheckBox, RadioButton, ScrollBar, DataGrid chrome
ถ้าไม่สลับตัวนี้ด้วยจะได้โหมดมืดครึ่งใบ

ตั้ง **ก่อน** วาง palette ของเราเสมอ เพราะการ set ThemeMode ทำให้ WPF ไปยุ่งกับ
`Application.Resources.MergedDictionaries` เอง (แทรก Fluent dictionary เข้ามา) — `ThemeService`
จึงหา palette ด้วย key `Theme.Name` ไม่ใช่ด้วย index ที่เลื่อนได้

## 2. แถบหัวหน้าต่างวาดเอง — และเหตุผลที่ไม่ใช่เรื่องความสวย

**บน Windows 10 build 19045 แถบหัวหน้าต่างของ Windows ไม่ยอมเป็นสีเข้ม**
`DWMWA_USE_IMMERSIVE_DARK_MODE` (attribute 20) ถูกรับค่าเรียบร้อย — `DwmGetWindowAttribute` อ่านกลับมา
ได้ `1`, `hr = 0` — แต่ยังวาดขาวอยู่ดี (ของนี้เริ่มทำงานจริงบน Windows 11) ทดสอบซ้ำแล้วรวมถึงสั่ง
`SetWindowPos(SWP_FRAMECHANGED)` บังคับวาดกรอบใหม่ ก็ยังขาว

ผลคือถ้าไม่วาดแถบหัวเอง โหมดมืดจะมีแถบขาวพาดหัวทุกหน้าต่าง ซึ่งดูเหมือนของเสีย

`AppDialogWindow` (ใน `Theme/Controls.xaml`) จึงวาดแถบหัวเอง โดย:

- ใช้ **`WindowChrome`** ไม่ใช่ `WindowStyle="None"` — `WindowChrome` ยกเฉพาะ *การวาด* มาให้เรา แต่
  ยังคง *พฤติกรรม* ของ Windows ไว้ครบ (snap ที่ขอบจอ, ปุ่มบนแถบงาน, เงา, resize ด้วยขอบ)
- `ThemeService.ApplyToWindow` **ยังเรียก DWM อยู่** เผื่อเครื่อง Windows 11 และเผื่อขอบที่เราไม่ได้วาด
- ปุ่มย่อ/ขยายโผล่ตาม `ResizeMode` ของแต่ละหน้าต่าง
- ตอน `Maximized` ต้อง `Padding="7"` — เป็นท่าแก้มาตรฐานของ WindowChrome ที่หน้าต่างจะขยายเลยขอบจอ
- ปุ่มปิด/ย่อ/ขยายใช้ **attached property** (`DialogChrome.IsCloseButton` ฯลฯ) ไม่ใช่ `Click` handler
  เพราะปุ่มอยู่ใน template ที่ใช้ร่วมกัน ไม่มี code-behind ตัวไหนเป็นเจ้าของ และ
  `SystemCommands.CloseWindowCommand` ก็ไม่มี `CommandBinding` ให้เมื่อหน้าต่างใช้ template ของตัวเอง
- ต้องมี `<AdornerDecorator>` ครอบ `ContentPresenter` — ปกติ template มาตรฐานของ WPF ใส่ให้ ถ้าไม่มี
  ToolTip / validation adorner จะไม่ปรากฏเลย
- **แถบหัวเข้มเสมอทั้งสองธีม** (2026-09-10 ตามที่ผู้ใช้ขอ) ใช้ชุด `Brush.Sidebar.*` ซึ่งมีไว้สำหรับ
  "พื้นผิวที่เข้มไม่ว่าธีมไหน" อยู่แล้ว จึงไม่ต้องมี token ชุดที่สาม และได้ผลพลอยได้คือแถบหัวต่อเนื่อง
  เป็นชั้นสีเดียวกับ sidebar **ปุ่มปิด/ย่อ/ขยายต้องใช้สีชุด Sidebar ตามไปด้วย** ไม่งั้นในธีมสว่างจะ
  กลายเป็นไอคอนเทาอ่อนบนพื้นเข้ม = มองแทบไม่เห็น
- **ขอบหน้าต่างใช้ `Brush.Sidebar.Border` ไม่ใช่ `Brush.Border.Strong`** — ตัวหลังเป็นเทาอ่อนในธีมสว่าง
  ซึ่งกลายเป็นเส้นขาวล้อมรอบแถบหัวสีเข้ม

### 2.1 หน้าต่างย่อยจัดกึ่งกลางด้วย `WindowStartupLocation="CenterOwner"`

**ใช้ของ WPF เอง อย่าเขียนตัวคำนวณเอง** (ตัดสินใจ 2026-09-10 หลังลองทั้งสองแบบ)

ประวัติสั้น ๆ เพื่อไม่ให้วนกลับไปทำซ้ำ: เคยมีสองกลไกปนกัน — 9 บานคำนวณตำแหน่งเองใน `Loaded` ผ่าน
helper ของเราเอง (ลบทิ้งแล้ว) ส่วนอีก 7 บานใช้ `CenterOwner` วัดจริงแล้วได้ผลดังนี้

| วิธี | ระยะเยื้องที่วัดได้ |
|---|---|
| `CenterOwner` ของ WPF | `(0.0, -6.0)` |
| helper + รอบจัดซ้ำหลัง layout นิ่ง | `(0.0, 0.0)` |

**เลือก `CenterOwner`** แม้จะเยื้อง 6px เพราะ 6px มองไม่เห็น ส่วนตัวคำนวณเองมีปัญหาที่ใหญ่กว่านั้น:

- **`SystemParameters.WorkArea` คืนพื้นที่ของจอหลักเท่านั้น** ตัวหนีบขอบในนั้น จึงจะ**ลาก dialog
  กลับมาจอหลัก**ถ้าหน้าต่าง Dashboard อยู่บนจอที่สอง (อ่านจากโค้ดได้ตรง ๆ ยังไม่ได้ทดสอบบนเครื่องสองจอ)
- รอบจัดซ้ำทำให้หน้าต่างขยับอีกครั้งหลังโผล่มาแล้ว

6px นั้นมาจาก `SizeToContent`: `ConfirmWindow` สูง 192 ตอนวัด แล้วหดเหลือ 180 ทีหลัง — ถ้าวันหนึ่ง
เยื้องจนน่ารำคาญจริง ให้แก้ที่ต้นเหตุ (ตรึงความสูงแทน `SizeToContent`) ไม่ใช่กลับไปเขียนตัวคำนวณเอง

วัดได้ด้วยสวิตช์ `center-test` (ดู §6) ซึ่งพิมพ์ระยะเยื้องเป็นตัวเลขลง `console.log` — ภาพนิ่งพิสูจน์
เรื่องนี้ไม่ได้ เพราะ `RenderTargetBitmap` วาด visual tree ของหน้าต่างเดียว ไม่เห็นตำแหน่งสัมพัทธ์

### 2.2 overlay ดูจอเต็มจอห้ามแย่ง focus จากหน้าต่างอื่น

`LiveViewFullscreenOverlay_IsKeyboardFocusWithinChanged` ดึง keyboard focus กลับมาที่ overlay เพื่อให้
การส่งคีย์ไปเครื่องปลายทางทำงานต่อเนื่อง แต่เงื่อนไขเดิมดึงกลับ **ทุกครั้งที่ focus หลุด ไม่ว่าหลุดไปไหน**
พอเปิดหน้าต่างทับ (เช่นหน้ารายงานผล) หน้าต่างนั้นจะถูกแย่ง focus คืนทันทีจนกดปิดไม่ได้ (ผู้ใช้รายงาน
2026-09-10)

สิ่งที่ตั้งใจกันไว้แต่แรกคือ popup/ContextMenu **ภายใน Dashboard เอง** ไม่ใช่หน้าต่างที่ผู้ใช้ตั้งใจเปิด
**เช็ค `IsActive` ของ Dashboard ก่อนเสมอ** — ถ้าไม่ได้ active แปลว่าผู้ใช้กำลังคุยกับหน้าต่างอื่น อย่าไปยุ่ง
ตรวจได้ด้วยสวิตช์ `focus-test` ซึ่งเปิดหน้าต่างทับตอนอยู่เต็มจอแล้ว log ว่าใครถือ focus จริง

## 3. Sidebar คือ `TabControl` ตัวเดิม

หน้า Dashboard **ไม่ได้** ถูกเขียนใหม่เป็น navigation แบบ ViewModel — มันยังเป็น `TabControl` ตัวเดิม
เปลี่ยนแค่ `ControlTemplate` (ย้าย panel ที่ `IsItemsHost` ไปคอลัมน์ซ้าย) กับ `ItemContainerStyle`
(แถวเมนูแทนแท็บแนวนอน) ผลคือ `MainTabControl_SelectionChanged`, `ScreenViewTabItem`,
`AuditLogTabItem`, `LiveViewTabItem` และโค้ดที่สั่งสลับแท็บเองยังทำงานเหมือนเดิมทั้งหมด

สามอย่างที่ต้องรู้:

- **`Nav.Group`** — `TabControl` มี items host ได้ panel เดียว จะแทรกหัวข้อกลุ่มคั่นระหว่าง item ไม่ได้
  จึงให้ *แถวแรกของกลุ่ม* วาดหัวข้อของตัวเอง แล้วซ่อนเมื่อค่าว่าง
- **`Nav.IsCollapsed`** ประกาศเป็น `Inherits` — ตั้งที่ `TabControl` ตัวเดียวแล้วไหลลงไปถึงทุกแถวเมนู
  หัวข้อกลุ่ม และปุ่มท้าย sidebar พร้อมกัน โดยไม่ต้องไล่หา element ข้าม namescope
- **`Nav.TopBar` / `Nav.StatusBar`** — แถบบนกับแถบสถานะถูก *ส่งเข้า* template ผ่าน attached property
  ไม่ได้เขียนไว้ใน template ตรง ๆ เพราะ **element ที่ประกาศใน `ControlTemplate` ไม่มี field จาก
  `x:Name` ให้ code-behind เรียกถึง** และ `DashboardWindow.xaml.cs` แตะ `StatusText` อย่างเดียว 22 จุด
  วิธีนี้ทำให้รื้อโครงหน้าจอทั้งหมดได้โดยไม่แตะ code-behind สักบรรทัด

ลำดับแท็บถูกจัดใหม่ให้กลุ่มติดกัน (Clients, Screen View, Live View, Logs | Rules | Audit Log, Users)
ปลอดภัยเพราะ **ไม่มีโค้ดตรงไหนอ้างแท็บด้วย index** — ตรวจก่อนย้ายแล้ว มีแต่ `SelectedItem` กับชื่อ TabItem

### 3.1 กลุ่มจริงของ sidebar (WP6, 2026-10-30)

`Nav.Group` ที่ใช้งานจริงตอนนี้มี 4 กลุ่ม (แถวที่ `Nav.Group=""` คือสมาชิกต่อจากหัวข้อกลุ่มด้านบน ไม่ใช่
แท็บไม่มีกลุ่ม — ดู §3 ข้อ `Nav.Group`):

| กลุ่ม | แท็บ |
|---|---|
| ห้องเรียน | Clients, Screen View, Live View |
| กฎ | กฎโปรแกรม, Program Review, Website Control |
| บันทึก | Logs, Audit Log |
| ระบบ | ผู้ใช้, ตั้งค่า |

ผังที่นั่งและโหมดสอบใน roadmap ยังไม่มีแท็บจริง (ขั้น 2+) — รายการข้างบนคือสิ่งที่มีอยู่จริงในโค้ด
ไม่ใช่รายการที่ตั้งเป้าไว้

### 3.2 หน้าต่างลอย 3 บานกลายเป็นหน้าใน shell แล้ว (WP6)

`ProgramReviewWindow`, `WebsiteControlWindow` และ `SettingsWindow` **ไม่มีอยู่แล้ว** — แปลงเป็น
`UserControl` ในไฟล์ชื่อใหม่ (`ProgramReviewPage`, `WebsiteControlPage`, `SettingsPage`) ที่ถูกประกาศเป็น
เนื้อหาแท็บโดยตรงใน `DashboardWindow.xaml` ลักษณะการแปลงเหมือนกันทั้งสามหน้า:

- logic เดิมทั้งหมดยกมาไม่เปลี่ยน ต่างกันแค่ (1) ไม่มี `ApiClient` ให้ผ่าน constructor อีกต่อไป (หน้าถูก
  สร้างโดย XAML ของ Dashboard ก่อน `ApiClient` จะพร้อม) จึงรับผ่านเมธอด `Initialize(ApiClient)` ที่
  `DashboardWindow`'s constructor เรียกทันทีหลัง `InitializeComponent()` แทน
- ข้อความผลลัพธ์/error เดิมที่เคยโชว์ในหน้าต่างของตัวเอง ย้ายไปใช้ `ToastService` (ดู §5)
- โหลดข้อมูลใหม่ทุกครั้งที่ "เปิด" หน้านี้ (ผูกกับ `IsVisibleChanged`) แทนที่จะโหลดครั้งเดียวตอนสร้าง
  หน้าต่าง — เพราะตอนนี้หน้าถูกสร้างครั้งเดียวตอน Dashboard เปิด ไม่ได้ถูกสร้างใหม่ทุกครั้งที่ "เปิด"
  เหมือนตอนเป็นหน้าต่างแยก

ปุ่มเดิมที่เคยเปิดหน้าต่างเหล่านี้ (`ProgramControlButton_Click`/`WebsiteControlButton_Click` ใน
`DashboardWindow.xaml.cs`) ไม่มีอยู่แล้วเช่นกัน — เข้าหน้าผ่าน sidebar โดยตรง

## 4. ไอคอน — ไม่มี emoji ไม่มี icon font

`Theme/Icons.xaml` เป็น port ของ `Components/Icon.razor` แบบตรงตัว (Geometry บน canvas 24×24 เท่ากับ
`viewBox="0 0 24 24"`) **สองไฟล์นี้ต้องมีชุดเดียวกันเสมอ** เพิ่มที่ไหนต้องเพิ่มอีกที่ด้วย — ตอนนี้ 34 ตัว
(`grid` / `minus` / `square` เพิ่มมาจากฝั่ง WPF และใส่กลับเข้า `Icon.razor` แล้วแม้เว็บยังไม่ได้ใช้)

- **`IconPresenter` ชดเชยความหนาเส้น**: `StrokeThickness = 2.0 × 24 / IconSize` (1.75 ที่ ≥28px)
  ถ้าไม่ชดเชย ไอคอน 16px จะได้เส้น 1.33px (บางจนซีด) และ 32px ได้ 2.67px (หนาเหมือนปากกาเมจิก)
  → **ความหนาเส้นจึงไม่เท่าฝั่งเว็บโดยเจตนา** (เว็บปล่อยให้ scale ตาม viewBox) ส่วน geometry เหมือนกันเป๊ะ
- **จุดที่เป็น degenerate line ใน SVG** (`x2="3.01"`) WPF วาดออกมาเป็น *ไม่มีอะไรเลย* แม้ตั้ง round cap
  จึงถูกแทนด้วย `EllipseGeometry` รัศมี **0.1** — เล็กเกือบศูนย์แต่ไม่ใช่ศูนย์ เพื่อให้พอถูกตีเส้นหนา `t`
  จะได้จุดทึบขนาด ~`t` เท่ากับที่ round cap ของ SVG ทำ (รัศมี 1 จะกลายเป็นวงแหวนกลวงตอนไอคอนใหญ่)
- **ไม่มี emoji ในโค้ดฐานนี้มาตั้งแต่แรก** สิ่งที่มีคืออักขระเรขาคณิตที่ทำหน้าที่เหมือนไอคอน
  (`ACTIONS ▾`, `◀ PREV`, `NEXT ▶`, `✕`, `←`) ซึ่งถูกแทนด้วยไอคอนเวกเตอร์หมดแล้ว — ปัญหาเดียวกับ emoji
  คือรูปร่างขึ้นกับ font ที่ระบบ fallback มาให้ ไม่ใช่ของเรา

## 5. หลักการที่ยึด (และที่จงใจไม่ยึดตามเว็บ)

- **Toast มุมขวาล่างแทนข้อความผลลัพธ์ที่เคยแทรกในหน้า** (WP6, 2026-10-30) — `ToastService` (static,
  ดู `Services/ToastService.cs`) + `ToastHost` วางอยู่ชั้นบนสุดของ `DashboardWindow` จุดเดียว
  สำเร็จ/ข้อมูลหายเองใน 4 วินาที · error ค้างจนกดปิด · ซ้อนกันสูงสุด 3 อัน (อันที่ 4 ดันอันเก่าสุดออก) ·
  ข้อความซ้ำกับอันที่โชว์อยู่ไม่เพิ่มอันใหม่ แค่นับเวลาใหม่ · รองรับลิงก์ action ในตัว (เช่น "ดูผล")
  เรียกได้จากทุกหน้า/หน้าต่างย่อยโดยไม่ต้องส่ง reference ต่อกัน เพราะเป็น static — toast ที่ถูกเรียกก่อน
  `ToastHost` จะมี (เช่นตอน login เสร็จใน `MainWindow`, ก่อน `DashboardWindow` จะเปิดด้วยซ้ำ) ค้างอยู่ใน
  `ToastService.Items` แล้วโผล่ทันทีที่ `ToastHost` ถูกสร้าง **toast ไม่ได้มาแทนทุกอย่าง**: อะไรที่ต้องให้
  ครูตัดสินใจก่อน (ลบ/ปิดทั้งระบบ) ยังเป็น `ConfirmWindow` เหมือนเดิม และ "สถานะของทั้งระบบ" ที่ต้องเห็น
  ตลอดเวลาอยู่ที่แถบหัว (ดูข้อถัดไป) ไม่ใช่ toast เพราะ toast หายไปได้แต่ปัญหายังอยู่
- **ประกาศสถานะทั้งระบบอยู่ที่แถบหัว ไม่ใช่แถบเตือนที่ดันเนื้อหาลง** (WP6, 2026-10-30) —
  `AnnouncementCenter` + `AnnouncementBar` แทนที่ `GlobalOffBanner` แถวเดิมที่ Collapsed/Visible สลับกัน
  (ซึ่งมีปัญหาคลาสเดียวกับข้อ "ห้ามให้อะไรแทรกเข้ามาเหนือตาราง" ด้านล่าง) แถบหัวสูงคงที่ 60px เสมอ
  **ทุกกรณี** เปลี่ยนแค่สี/ข้อความ/ปุ่มแก้ในตัว ใช้กับ: ปิดการบังคับใช้ทั้งระบบ, เชื่อมต่อ Server ไม่ได้,
  SignalR กำลังเชื่อมต่อใหม่ หลายเรื่องพร้อมกัน = แสดงเรื่องร้ายแรงที่สุด + ป้าย `+N` ให้กดดูที่เหลือ
- **แผงข้อมูลเครื่อง (inspector) เป็น overlay สไลด์จากขวาทับอยู่บน grid ไม่ใช่คอลัมน์ที่ดันตารางแคบลง**
  (WP6, 2026-10-30) — หุบเหลือแถบแคบได้ (ไอคอนปุ่มเดียว) และ Esc หรือปุ่ม ✕ ปิดได้ เปิด/ปิด/หุบ/กาง
  ไม่ทำให้ `ClientsGrid` ขยับเลยแม้แต่พิกเซลเดียว (วัดได้ด้วย `--ui-preview --inspector-collapsed`
  เทียบกับ `--ui-preview` เฉยๆ — ดู §6)
- **เวลาแสดงเป็นเวลาไทย (UTC+7) โดยปริยาย ไม่ใช่ UTC ดิบจาก Server** (WP6, 2026-10-30) — ทุกคอลัมน์เวลา
  ผ่าน `DisplayTimeConverter`/`TimeColumn` (ดู `Services/TimeDisplay.cs`) สลับกลับเป็น UTC ได้จากหน้า
  ตั้งค่า (`UiSettings.ShowTimesInUtc`) หัวคอลัมน์ขึ้น "(UTC)" ต่อท้ายเฉพาะตอนเลือกโหมด UTC เท่านั้น
  (โหมดไทยซึ่งเป็นค่าเริ่มต้นไม่ขึ้นหน่วยกำกับ เพื่อไม่ให้ทุกหัวคอลัมน์รกเกินจำเป็น)
- **badge เป็นเม็ดสีอ่อน ไม่ใช่ป้ายทึบ** — สีสถานะทับพื้นการ์ดด้วย alpha 14–20% + ตัวหนังสือสีสถานะ
  + จุดนำหน้า เก็บเป็น *alpha* ไม่ใช่สีทึบที่ผสมไว้แล้ว เพื่อให้ตามสีการ์ดไปเองถ้าวันหลังปรับ
  (เหตุผลเดียวกับที่ฝั่งเว็บ `color-mix` กับ `var(css:card)` ไม่ใช่กับสีขาว)
- **`Danger.Fill` ≠ `Danger.Default`** — ในธีมมืด `#F87171` เป็นสีแดงที่เลือกมาให้ *อ่านออกบนพื้นเข้ม*
  จึงสว่างเกินกว่าจะเป็นพื้นหลังของตัวหนังสือขาว (ขาวบน `#F87171` ≈ 2.5:1 ตกเกณฑ์) ปุ่มอันตรายจึงถม
  ด้วย `#DC2626` (≈ 4.8:1) **นี่เป็นจุดที่จงใจต่างจากเว็บ** ซึ่ง `.btn-danger` ยังใช้สีเดียวกันทั้งคู่
- **การ์ดตัวเลขคิดจากข้อมูลทั้งหมดเสมอ ไม่ใช่จากผลที่กรองแล้ว** — ไม่งั้นกด "ออนไลน์" แล้วการ์ด
  "ออฟไลน์" กลายเป็น 0 ซึ่งอ่านเหมือนเครื่องหายไปจากระบบจริง ๆ
- **แผงรายละเอียดขวาโผล่เมื่อเลือกเครื่องเดียวเท่านั้น** — เลือกหลายเครื่องคือโหมดสั่งงานหมู่ ซึ่งมี
  แถบเลือกด้านบนรับหน้าที่อยู่แล้ว
- **ห้ามให้อะไรแทรกเข้ามาเหนือตาราง Clients** (แก้ 2026-09-10) — กลุ่ม "ที่เลือก" ใช้
  `Visibility="Hidden"` ไม่ใช่ `Collapsed` และอยู่ **แถวเดียวกัน** กับกลุ่ม "ทั้งห้อง"
  ของเดิมเป็นแถวแยกที่ Collapsed ไว้ พอคลิกเลือกเครื่องหนึ่ง แถวนั้นแทรกเข้ามาแล้วดันตารางลงไป
  ~45px คลิกครั้งถัดไปจึงไปโดนเครื่องคนละตัวกับที่เล็งไว้ — ในหน้าจอที่มีปุ่ม SHUTDOWN อยู่ด้วย
  นั่นไม่ใช่เรื่องความสวยงาม **ถ้าจะเพิ่มอะไรเหนือตาราง ต้องกันที่ไว้ตลอดเวลา**
  (ตรวจได้ด้วย `--ui-preview` เทียบกับ `--ui-preview --select` แล้วหา vertical offset ที่ตรงกันที่สุด
  ต้องได้ 0)
- **คำสั่งระดับห้องต้องกดได้โดยไม่ต้องเลือกเครื่องก่อน** (แก้ 2026-09-10) — เดิมทางเข้า ACTIONS มีที่
  แถบเลือกที่เดียว และ handler ก็ปฏิเสธถ้าเลือก 0 เครื่อง แปลว่าจะสั่งทั้งห้องต้องไปเลือกเครื่องที่
  ไม่ได้ตั้งใจจะสั่งก่อน ตอนนี้ `ActionPanelWindow` โหมด bulk รับ selection ว่างได้ และจะปิดตัวเลือก
  "เครื่องที่เลือกไว้ (0 เครื่อง)" พร้อมบังคับเป็น "ทุกเครื่อง" (ห้ามปล่อยให้เลือกเป้าที่มี 0 เครื่อง
  ไม่งั้นกดสั่งแล้วเงียบ)
- **แถบเตือน gate ปิด เป็นแถบเต็มความกว้างใต้แถบบน ไม่ใช่เม็ดสีในแถบบน** — แถบบนสูง 60px และมี
  สถานะกับปุ่ม REFRESH อยู่แล้ว ยัดคำเตือนสองบรรทัดลงไปทำให้บรรทัดที่สองโดนตัด และปุ่ม "เปิดกลับ"
  ในแถบเตือน **ต้องอยู่ต่อ** แม้แท็บ Clients จะมีสวิตช์ของตัวเองแล้ว เพราะแถบเตือนเห็นจากทุกแท็บ
  ส่วนสวิตช์นั้นอยู่แค่แท็บเดียว
  สวิตช์ตัวนี้ถูก **เอาออกจากเมนูรูปเฟือง** แล้ว (2026-09-10) เหลือสองทางที่มองเห็นได้โดยไม่ต้องเปิด
  เมนูก่อน ซึ่งเป็นหัวใจของบั๊กเดิม
- **`Brush.Text.OnStatusFill` สำหรับตัวหนังสือบนพื้นสีสถานะ** (แก้ 2026-09-10) — พื้นเตือนสีเหลือง
  เป็นสีเดียวกันทั้งสองธีม ตัวหนังสือที่วางทับจึงต้องเป็นสีเดียวกันทั้งสองธีมด้วย **ห้ามใช้
  `Text.Primary`** เพราะในธีมมืดมันคือขาวนวล = ขาวบนเหลือง อ่านไม่ออก (เป็นบั๊กเดียวกับที่เคยแก้ไป
  แล้วกับ badge "Warning" แล้วเผลอทำซ้ำตอนเขียนแถบเตือน) ปุ่มที่วางบนพื้นแบบนี้ใช้ `ButtonOnStatus`
  ซึ่งเป็นเม็ดสีเข้ม — `ButtonPrimary` (ส้ม) บนเหลืองแยกกันแทบไม่ออก
- **ปุ่ม Tailscale ซ่อนไว้เป็นค่าเริ่มต้น** (`UiSettings.ShowTailscaleActions`, เปิดได้จากหน้า Settings)
  — LOCK / UNLOCK / STATUS / LOGIN เป็นงานดูแลเครือข่าย ไม่ใช่งานคุมห้องเรียน แต่มันนั่งปนอยู่กับ
  LOCK WORKSTATION และ SHUTDOWN ซึ่งกดจริงทุกวัน `ApplyTailscaleVisibility()` ถูกเรียกจาก
  **constructor ทุกตัว** ของ `ActionPanelWindow` (ทั้งโหมดเครื่องเดียวและโหมดหมู่) เพราะโจทย์คือ
  "ถ้าปิดไว้ต้องไม่โผล่ในหน้า actions ทุกหน้า" — เรียกแค่ตัวเดียวจะหลุดทันทีในอีกโหมด
  และซ่อนที่ `Grid` ที่ครอบอยู่ ไม่ใช่ซ่อนแค่ปุ่ม ไม่งั้นเหลือช่องว่างสองแถวค้างไว้
- **ยืนยันด้วยการพิมพ์ชื่อ ใช้เฉพาะปุ่มลบ** (ลบกฎ / ลบผู้ใช้) ไม่ใช้กับปิดเครื่องทั้งห้อง — ปิดเครื่อง
  กวนแต่ทำใหม่ได้ ส่วนของที่ลบไปแล้วเอาคืนไม่ได้ แรงเสียดทานที่ใส่ไปทุกที่จะกลายเป็นพิธีกรรมที่คนกดผ่าน
  โดยไม่อ่าน ซึ่งแย่กว่าไม่มี
- **ไม่ทำ responsive / breakpoint** — นั่นเป็นงานของ OnlineConsole ฝั่ง WPF มีแค่ sidebar ที่ย่อได้
- **ไม่ตัดฟีเจอร์ลงเพื่อให้เท่าเว็บ** — WPF Console มี Live View (กำแพงจอแบบ CCTV), remote control
  เต็มจอ และ block student input ซึ่ง OnlineConsole ไม่มี (12-tile grid ถูกถอดออกเพราะแบนด์วิดท์
  2026-09-04) เอามาแค่ "ภาษาดีไซน์" ไม่ใช่ "ขอบเขตฟีเจอร์"

## 5.1 กติกาการตั้งชื่อปุ่ม (2026-09-10)

มาจาก feedback ของผู้ใช้จริงว่า "บางคำไม่ชัดเจน ไม่รู้ว่ากดแล้วจะเกิดอะไรขึ้น" ตรวจแล้วพบสองสาเหตุ:

1. **ปนสองภาษาโดยไม่มีกฎ** — ปุ่มเก่าเป็นอังกฤษตัวใหญ่ (`SHUTDOWN`, `TOGGLE`, `RESET PW`) ปุ่มใหม่
   เป็นไทย ครูอ่านแผงเดียวที่มีทั้งสองแบบ (ฝั่ง OnlineConsole เป็นไทยเกือบหมดอยู่แล้ว — ดูจอ / คำสั่ง /
   ส่งข้อความ / อนุญาต / บล็อก การเปลี่ยนมาเป็นไทยจึงเป็นการ **ปิด**ช่องว่างกับเว็บ ไม่ใช่เปิดใหม่)
2. **มีกริยาแต่ไม่มีกรรมหรือขอบเขต** — `TOGGLE` สลับอะไรเป็นอะไร, `DELETE` ลบอะไร,
   `SETTINGS...` ซ้ำกับ Settings ของแอปเอง, `CONFIG RULE...` จริง ๆ คือ "ยกเว้นกฎเฉพาะเครื่องนี้",
   `ADD SELECTED TO GRID` คำว่า grid เป็นภาษาโปรแกรมเมอร์

**กติกาที่ใช้ เรียงตามลำดับความสำคัญ:**

- **กริยาก่อน แล้วกรรม แล้วขอบเขตถ้าอ่านผิดได้** (`เครื่องนี้` / `ทุกเครื่อง`)
- **ปุ่มที่สลับสถานะต้องบอก "ผลที่จะเกิดถ้ากด" ห้ามใช้คำว่า "สลับ"** — ปุ่มในตาราง Rules ผูกกับ
  `RuleDto.ToggleActionText` (`ปิดใช้` / `เปิดใช้`) แทนที่จะเขียน TOGGLE เหมือนกันทุกแถวจนต้องไล่อ่าน
  คอลัมน์สถานะก่อนทุกครั้ง
  **ข้อยกเว้นเดียว** คือปุ่มสลับแบบหมู่ใน `ActionPanelWindow` ที่กลับสถานะของ *แต่ละเครื่อง* ตามค่าเดิม
  ของเครื่องนั้น — มันบอกผลลัพธ์เดียวไม่ได้จริง ๆ จึงเขียนตามความจริงว่า "สลับ" แล้วอธิบายใน ToolTip
  ดีกว่าตั้งชื่อที่ฟังดูชัดแต่ผิด
- **ปุ่มยืนยันบอกการกระทำ ไม่ใช่คำว่า "ยืนยัน"** — `ConfirmWindow.Show(..., confirmText:)` ตอนกำลังจะ
  สั่งปิด 40 เครื่อง ปุ่มที่เขียนว่า YES บังคับให้ต้องย้อนไปอ่านข้อความใหม่ว่ากำลังตอบตกลงกับอะไร
- **ชื่อเฉพาะคงภาษาอังกฤษ**: Tailscale, VNC, GUID, Authenticode, Client GUID
- **ไม่ใช้ ALL CAPS** — ในภาษาไทยไม่มีความหมาย และในภาษาอังกฤษก็อ่านช้ากว่า
- **ข้อความอธิบายที่อ้างชื่อปุ่ม ต้องแก้ตามทุกครั้งที่เปลี่ยนชื่อปุ่ม** — เจอจริงตอนทำรอบนี้: empty state
  ของแท็บ Rules ยังเขียนว่า "กด ADD RULE" ทั้งที่ปุ่มชื่อ "เพิ่มกฎ..." ไปแล้ว ซึ่งเป็นอาการเดียวกับที่
  ผู้ใช้บ่นนั่นแหละ แค่ห่างออกไปหนึ่งขั้น
- **ป้ายที่สั้นเพราะที่ไม่พอ ต้องมี ToolTip เสมอ** เช่น ปุ่ม `คำสั่ง` ในแถบเลือก (ขอบเขตอยู่ในเม็ดสี
  ข้าง ๆ ที่เขียนว่า "เลือก N เครื่อง" อยู่แล้ว)

หัวคอลัมน์ตารางถูกแปลไปพร้อมกันทั้งหมด ไม่ใช่เฉพาะบางตาราง — แปลครึ่งเดียวแย่กว่าไม่แปลเลย
คอลัมน์ที่ข้อความไทยยาวกว่าเดิมถูกขยายความกว้างด้วย เพราะภาษาไทยไม่มีช่องว่างระหว่างคำ พอโดนตัด
แล้วความหมายหายทั้งคำ ไม่ได้ค่อย ๆ เลือนแบบภาษาอังกฤษ

## 6. เครื่องมือตรวจงาน UI (มีเฉพาะ build แบบ Debug)

`installer/publish-all.ps1` publish ด้วย `-c Release` เสมอ สวิตช์พวกนี้จึงไม่มีอยู่จริงในของที่ส่งขึ้น
เครื่องครู — ทั้งหมดอยู่ใน `#if DEBUG`

```
OnionProcOparetor.Console.exe --ui-preview                       เปิด Dashboard พร้อมข้อมูลปลอม 5 เครื่อง (+ 2 ห้องปลอม - WP3)
                             --theme=light|dark                 บังคับธีมสำหรับถ่ายภาพ ไม่บันทึกลง console-settings.json (WP6)
                             --fullscreen                        เปิดหน้าดูจอเต็มจอค้างไว้ (ปกติต้องมี VNC จริง)
                             --center-test                       วัดว่าหน้าต่างย่อยอยู่กึ่งกลางจริงไหม (ดู console.log)
                             --tab="Audit Log"                   เลือกแท็บก่อนถ่าย
                             --dialog=confirm-type               เปิดหน้าต่างย่อยแทน (16 แบบ รวมหน้า login - WP7 หน้าล็อกอินใหม่)
                             --select                            เลือกแถวแรกไว้ (ใช้เทียบว่าตารางขยับไหม)
                             --global-off                        ตั้ง gate ทั้งห้องเป็นปิด (ให้แถบเตือนที่หัวโผล่ - WP6)
                             --toasts                            ใส่ toast ตัวอย่างครบ 3 ชนิด (สำเร็จ+ลิงก์ / ข้อมูล / error - WP6)
                             --announce                          ใส่ประกาศ "Server หลุด" + "อัปเดตสดหลุด" เพิ่ม ตรวจแถบหัว/ปุ่ม +N (WP6)
                             --inspector-collapsed               เลือกแถวแรกแล้วหุบแผง inspector เหลือแถบแคบ (WP6)
                             --sidebar-expanded                  กาง sidebar โดยไม่บันทึกทับค่าจริงบนเครื่องนี้ (WP6)
                             --shot=C:\path\out.png              เรนเดอร์เป็น PNG แล้วปิดโปรแกรม
```

มีไว้เพราะ **เครื่อง dev เครื่องนี้รัน Server ตัวจริงอยู่ด้วย** การจะดู Dashboard สักทีไม่ควรต้อง
login เข้าเซิร์ฟเวอร์ของจริง — โหมดนี้ใช้ `ApiClient` ที่ยังไม่ได้ login ทุก API call จึงล้มเหลวหมด
โดยเจตนา เห็นแต่โครง UI

**`--shot` เรนเดอร์ในแอปด้วย `RenderTargetBitmap` ไม่ใช่จับภาพหน้าจอ** และนี่ไม่ใช่เรื่องรสนิยม:

| วิธี | ปัญหาที่เจอจริงระหว่างทำงานนี้ |
|---|---|
| `CopyFromScreen` | จับภาพ **เบราว์เซอร์ที่บังอยู่ข้างหน้า** มาแทนหน้าต่างแอป |
| `PrintWindow(PW_RENDERFULLCONTENT)` | คืน **เฟรมขาวเปล่า** เมื่อหน้าต่างถูกบัง |
| `SetForegroundWindow` | Windows ไม่ยอมให้ process เบื้องหลังแย่ง foreground |

`RenderTargetBitmap` วาดจาก visual tree ตรง ๆ จึงได้ภาพถูกต้องเสมอไม่ว่าหน้าต่างจะถูกบัง ย่อ หรือ
มีอะไรทับอยู่ **อย่าเปลี่ยนกลับไปจับภาพหน้าจอ**

หมายเหตุสำหรับสคริปต์: `Start-Process -ArgumentList` เอา array มาต่อด้วยช่องว่างโดย **ไม่ใส่เครื่องหมาย
คำพูดให้** — `--tab=Audit Log` จะกลายเป็นสองอาร์กิวเมนต์ ต้อง escape เอง

## 7. สิ่งที่ยังไม่ได้ทำ / ข้อจำกัดที่รู้อยู่

- **หน้าต่างราย client 6 บานยังเป็นหน้าต่าง** ปุ่มในแผงรายละเอียดเปิดหน้าต่างเดิม ไม่ได้ยุบเนื้อหา
  เข้ามาไว้ในแผง — `RunningProcessesWindow` กับ `ActionReportWindow` รับสตรีมสดผ่าน SignalR และ
  `ActionPanelWindow` สั่งงานเป็นชุด การรื้อโครงต้องทดสอบกับ Agent จริงในห้องแล็บ โครงแผงพร้อมแล้ว
  ยุบทีละบานทีหลังได้โดยไม่ต้องแก้ส่วนอื่น
- **CheckBox / RadioButton / ComboBox ยังใช้สี accent ของ Windows (ฟ้า) ไม่ใช่สีส้มของเรา** เพราะยังใช้
  template ของ Fluent อยู่ ถ้าจะแก้ต้อง re-template เอง (มีสำรวจไว้แล้วว่า `Shadcn.Wpf` ภายใต้ MIT มี
  template ของสามตัวนี้ที่ลอกมาปรับสีได้ ประมาณครึ่งชั่วโมงต่อตัว)
- **ยังไม่ผ่านการทดสอบภาคสนาม** ทั้งหมดนี้ตรวจด้วยภาพเรนเดอร์จริงของทุกหน้าจอในทั้งสองธีม แต่ยังไม่มี
  ใครใช้กับเซิร์ฟเวอร์จริงและ Agent จริง
- **ผังห้อง (seat layout)** พักไว้ก่อนตามที่ตกลง ถ้าทำเมื่อไหร่ **ต้องเก็บผังที่ Server เท่านั้น** เพราะ
  เครื่องแล็บทุกเครื่องรัน Reboot Restore Rx ของที่เขียนลงดิสก์ฝั่ง client หายทุก reboot
- **RBAC (ซ่อนเมนูตามบทบาท)** ยังไม่ทำตามที่ตกลง
