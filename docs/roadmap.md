> **ไฟล์นี้คือ "เมมกลาง"** ของงานรอบนี้ เก็บการตัดสินใจทั้งหมดที่คุยกับผู้ใช้แล้ว (29–30 ต.ค. 2569)
> และแบ่งงานขั้น 1 เป็น work package (WP) ให้ orchestrator แจกให้ worker ทำขนานกันได้
> กฎการทำงานร่วมกันอยู่ใน [`CLAUDE.md`](../CLAUDE.md)
>
> **Wireframe (แหล่งอ้างอิงหน้าตา):** https://claude.ai/artifact/7KbHzR3PrVq8r5upXrrJoW
> canvas เป็นของส่วนตัวผู้ใช้ worker จึงเปิดไม่ได้ **ต้นฉบับทุกหน้าสำเนาไว้แล้วที่ [`docs/wireframes/`](wireframes/README.md)** ให้อ่านหน้าที่เกี่ยวข้องก่อนทำงาน UI

## การตัดสินใจทั้งหมด (ยืนยันกับผู้ใช้แล้ว)

### Sign-in และบัญชี
- **บัญชีนักเรียน:** ล็อกอินด้วยเมลโรงเรียนหรือรหัสนักเรียน + รหัสผ่าน โดย Admin เป็นคนจัดการบัญชี **เป้าหมายคือ log รายบุคคล**
  - ไม่สร้างบัญชี Windows ให้นักเรียน (ชนกับ disk freeze) ล็อกอินที่ระดับแอปบนจอล็อกของ AgentTray แทน
- **Roster Manager** เป็นโปรแกรมแยก (WPF) แต่ใช้ Server และ DB ตัวเดียวกัน
  - **ข้อมูลนำเข้า:** CSV จับคู่คอลัมน์ได้ · รหัสนักเรียนซ้ำกับของเดิม = อัปเดตชื่อและห้องโดยไม่แตะรหัสผ่าน
  - **รหัสเริ่มต้น:** สุ่ม 6 หลักต่อคน + บังคับเปลี่ยนตอนล็อกอินครั้งแรก · พิมพ์ใบแจกได้ A4 ละ 10 ใบ · เก็บแบบ hash ย้อนดูไม่ได้
  - **เลื่อนชั้นปี:** ทำปีละครั้ง นักเรียนที่จบปิดบัญชีได้ และสำรอง DB ให้อัตโนมัติก่อนเลื่อน
- **การบังคับล็อกอินเปิด/ปิดได้ที่ตั้งค่า Server** (ทั้งระบบหรือเลือกห้อง)
  - เปิดอยู่: ไม่ล็อกอิน = ใช้เครื่องไม่ได้
  - ปิด: เครื่องที่ค้างอยู่หน้าล็อกอินจะปลดเองภายใน 1 รอบ poll
  - สลับไปเปิด: ไม่เตะคนที่ใช้เครื่องอยู่ออกกลางคัน
- **ความปลอดภัยบัญชี:** ล็อกบัญชีเมื่อกรอกผิด 5 ครั้ง (ครูปลดได้) · รหัสขั้นต่ำ 6 ตัว · Teacher รีเซ็ตรหัสนักเรียนได้ (ปิดสิทธิ์ได้) · บัญชีเดียวล็อกอินเครื่องใหม่ = เตะเครื่องเก่าออก (ค่าเริ่มต้น) + บันทึก log
- **logout อัตโนมัติ:** เมื่อไม่ได้ใช้งาน N นาที (ค่าเริ่มต้น 15) และเมื่อปิด/รีสตาร์ทเครื่อง มีปุ่ม "ไม่ใช่ฉัน" ในเมนู tray
- **ไม่มีตาราง/คาบเรียน** เพราะวิชาอื่นขอยืมห้องและครูพานักเรียนเข้าคาบว่างบ่อย ห้องอยู่โหมดใช้งานทั่วไปเสมอ
  - รายงาน = "ประวัติการใช้เครื่อง" กรองตามช่วงเวลา ห้องคอม และห้องเรียนของนักเรียน ใช้ดูประกอบเท่านั้น ไม่ใช่ใบเช็คชื่อทางการ
- **Role มี 2 ระดับ**
  - **Admin:** ทำได้ทุกอย่าง
  - **Teacher:** คุมห้อง ดูจอ เปิดโหมดสอบ รีเซ็ตรหัสนักเรียน (ถ้าเปิดสิทธิ์) และเปิด Staff session ได้ แต่แก้กฎถาวร ผู้ใช้ ห้อง และตั้งค่าระบบไม่ได้
- **ชื่อที่แสดง (display name)** สำหรับบัญชี Admin/Teacher
  - ใช้แสดงทุกที่ที่คนเห็น เช่น "Staff session (ครูสมชาย)", "ล็อกโดย ครูสมชาย", ผู้ส่งข้อความ, แถบล่าง Console
  - เจ้าของบัญชีแก้เองได้ Admin แก้ให้ได้ · username ใช้ล็อกอินและแก้ไม่ได้
  - **Audit Log เก็บทั้ง username และชื่อที่แสดง ณ ตอนนั้น**
- **Staff session:** ครูล็อกอินที่เครื่องนักเรียนด้วยบัญชี Console
  - ปิดกฎทั้งเครื่องชั่วคราว: ค่าเริ่มต้น 30 นาที สูงสุด 120 นาที ต่อเวลาได้ จบเองเมื่อหมดเวลาหรือรีบูต
  - บันทึกเหมือนตอน admin ล็อกอิน Console (บัญชี + เครื่อง) และไม่นับเป็นการใช้เครื่องของนักเรียน
  - **ใช้กลไก token จาก Server แบบเดียวกับที่ใช้แทน `bypass/set`** (ดู WP2)
- **รหัสฉุกเฉิน (Server ล่ม):** ใช้ TOTP มาตรฐาน 6 หลัก เปลี่ยนทุก 30 วินาที secret ฝังมาตอนติดตั้ง Agent
  - ครูดูรหัสได้ 2 ทาง: แอป Authenticator หรือหน้าเว็บ Google Apps Script (จำกัดให้เปิดได้เฉพาะบัญชีครู และบันทึกว่าใครเปิดดู) · secret ของ Apps Script เก็บใน Script Properties
  - ปลดเครื่องได้แบบไม่ระบุชื่อ แล้วบันทึกย้อนหลังเมื่อ Server กลับมา
  - **ห้ามใช้ OnlineConsole แสดงรหัส** เพราะรันบนเครื่อง Server จึงล่มไปพร้อมกัน

### เครือข่ายและความปลอดภัย
- **HTTPS ด้วย self-signed certificate:** MSI ติดตั้งใบรับรองให้เครื่องนักเรียนเชื่อถือ **ต้องเสร็จก่อนเริ่มเก็บรหัสผ่านนักเรียน** · ช่วงย้ายระบบมีตัวเลือก "ยอมรับ HTTP เดิม"
- **Agent ตอนบูต: แข่งกันระหว่าง LAN กับ Tailscale โดยให้ LAN เป็นหลัก**
  - ยิง LAN ก่อน ถ้าไม่ตอบใน 2 วินาที ยิง Tailscale ตามไปด้วย ทางไหนตอบก่อนใช้ทางนั้น
  - ถ้าได้ Tailscale ให้ probe LAN อยู่เบื้องหลัง พอ LAN ติดค่อยสลับกลับ
  - หลังบูตแล้วใช้กติกาเดิม (เสีย 5 ครั้งสลับไป / ดี 7 ครั้งสลับกลับ ใน `Worker.cs`)

### จอนักเรียน (AgentTray)

### WP2-1: ป้องกันการเลี่ยง (browser hardening)
- **งาน:** ตั้งค่าเปิด/ปิดได้ทีละข้อจาก Server (เก็บในตารางตั้งค่าของระบบ)

- **เกณฑ์เสร็จ:** ทดสอบการเขียนและล้าง policy กับ key ทดลอง · Console บันทึกค่าได้จริง

  - AgentTray: ป้ายมุมขวาล่าง "โหมดสอบ · เหลือ N นาที"
  - Console: หน้าต่างเปิดโหมดสอบ + แท็บชุด Allow-list · OnlineConsole: หน้าเปิดโหมดสอบ
  - ประกาศ "โหมดสอบกำลังทำงาน" ในแถบหัวของ Console
- **เกณฑ์เสร็จ:** ทดสอบหมดเวลาเองทั้งฝั่ง Server และฝั่ง Agent (ตรรกะ) · ชุดสำเร็จรูปเปิดได้จริงในเบราว์เซอร์ (ทดสอบบนเครื่อง dev ด้วย key ทดลองไม่ได้ ให้ระบุไว้ว่าต้องทดสอบในแล็บ)

### WP2-4: ประวัติเว็บ (migration)
- **งาน:**
  - Agent สำเนาไฟล์ History (SQLite) ของ Chrome/Edge ของ user ที่ล็อกอินอยู่ แล้วอ่านเฉพาะ URL ใหม่ตั้งแต่ครั้งก่อน ส่งขึ้น Server เป็นชุดทุก 1 นาที
  - Server: ตาราง `WebVisit` (เครื่อง, เวลา, โดเมน, หัวเรื่อง, ถูกบล็อกหรือไม่) + retention ใช้ค่าเดียวกับ ActivityLog
  - Console: แท็บประวัติเว็บ (กรอง, สรุปเว็บที่เข้าบ่อย, ปุ่ม "บล็อกโดเมนที่เลือก")
  - คอลัมน์นักเรียนยังว่างจนกว่าขั้น 3 จะทำ
- **เกณฑ์เสร็จ:** อ่าน History ไฟล์ทดลองแล้วส่งขึ้น Server ทดสอบได้ · Console แสดงและกรองได้

## ขั้น M: Core + โมดูล และระบบสอบ (วางแผน 10 พ.ย. 2569)

> ลำดับ: **Pilot รอบ 1 (ผู้ใช้) ขนานกับ M0 → UI-10 → M1 → Pilot รอบ 2 → ขั้น 5 และงานที่เหลือ**
> งานอื่นใน roadmap พักไว้จนหลัง Pilot รอบ 2

### การตัดสินใจ (ยืนยันกับผู้ใช้แล้ว 10 พ.ย.)

**โครงระบบ**
- **Core + โมดูลที่เปิด/ปิดหรือติดตั้งเพิ่มได้** ยังไม่มีระบบ plugin หรือ hot-load: โค้ดทุกโมดูล build รวมไว้ แล้วคุม 2 ระดับ
  - **เปิด/ปิด:** สวิตช์อยู่ใน Server (`core.db`) Admin สั่งจากหน้าตั้งค่า · Agent รู้ผ่าน poll (รอด disk freeze) · Console/OnlineConsole ถาม `/api/modules` แล้วซ่อนเมนู · endpoint ของโมดูลที่ปิดตอบว่าโมดูลปิดอยู่
  - **ติดตั้งเพิ่ม:** เฉพาะส่วนที่เป็นโปรแกรมแยก เป็น feature ใน MSI ได้แก่ Exam Shell, Roster Manager, RemoteBridge, OnlineConsole
- **1 โมดูล = 1 DbContext + 1 ไฟล์ .db + โฟลเดอร์ migration ของตัวเอง** (แบบเดียวกับ `ActivityLogDbContext`) · ข้ามโมดูลอ้างกันด้วย ID ธรรมดา ไม่มี FK ข้ามไฟล์

| ส่วน | ตาราง / ของที่ติดตั้ง | ไฟล์ |
|---|---|---|
| Core | เครื่อง, คำสั่ง, กฎโปรแกรม + override + verdict, GlobalState, ผู้ใช้ครู + token, ห้อง + ที่นั่ง, backup, รหัสฉุกเฉิน, สวิตช์โมดูล | `core.db` |
| Activity Log | (แยกอยู่แล้ว) | `activitylog.db` |
| Website | กฎเว็บ, แหล่งรายการ, hardening, ชุด Allow-list, ประวัติเว็บ | `website.db` |
| Sign-in | นักเรียน, session, ตั้งค่า + Roster Manager | `signin.db` |
| เครื่องมือสอน | โปรแกรมที่เปิดได้, แจก/เก็บไฟล์ (ยกมือ/ส่งจอไม่มีตาราง) · รวมเป็นโมดูลเดียว | `teaching.db` |
| Exam | ใหม่ (M1) + Exam Shell | `exam.db` |
| RemoteBridge | ไม่มีตาราง | - |

- **DB เริ่มใหม่ตอนย้ายไปเครื่อง Server จริง** (ผู้ใช้จะกรอกข้อมูลใหม่ทั้งหมด) จึง **รวม migration เดิม 21 ตัวทิ้ง** ให้แต่ละ context เริ่มด้วย `InitialCreate` ได้ · กฎ additive ใน CLAUDE.md เริ่มใช้หลังย้ายเครื่อง
- **Sidebar สร้างจากรายการโมดูล** กรองตามโมดูลที่เปิด + บทบาท · กลุ่มพับได้และจำสถานะ · ต้องคงสิ่งที่ UI-13/UI-14 ตัดสินไว้ (ผู้ใช้/ออกจากระบบท้าย sidebar, ไม่มีป้ายกลุ่มซ้ำ)
- **บทบาทใหม่ "ผู้คุมสอบ" (Proctor):** เห็นเฉพาะหน้าสอบ ใช้ได้ทั้ง Console และ OnlineConsole (เช่นครูโรงเรียนอื่นในงานแข่งคุมจากมือถือ)

**ระบบสอบ (แทนโหมดสอบ allow-list เดิมของ WP2-2)**
- **ทำระบบสอบเอง** (สร้างโจทย์, ทำข้อสอบ, ตรวจ) ไม่ใช้ Google Forms · **Exam Shell = โปรแกรม WPF บนเครื่องนักเรียน ไม่มีเบราว์เซอร์** · คำตอบส่งขึ้น Server ทีละข้อ รีบูตแล้วล็อกอินกลับมาทำต่อได้
- **แบบโจทย์ v1:** ปรนัย/ถูก-ผิด, เติมคำสั้น (ตรวจอัตโนมัติด้วยรายการคำตอบที่ยอมรับ), อัตนัย (ครูตรวจเอง) · โจทย์และตัวเลือกใส่รูปได้ · ยังไม่รองรับสูตรคณิตศาสตร์
- **สร้างโจทย์:** นำเข้า Excel/CSV + แก้รายข้อใน Console · มีคลังโจทย์แยกจากชุดสอบ
- **ตัวตนผู้สอบ (ตั้งต่อชุดสอบหรือรอบสอบ):** บังคับล็อกอิน (ต้องเปิดโมดูล Sign-in) / Guest กรอกชื่อ + โรงเรียน + เลขที่นั่งสอบ / Guest ไม่ระบุตัว · เหตุผล: ห้องนี้เคยถูกยืมไปจัดงานแข่งของโรงเรียนอื่น
- **คะแนน:** ครูเลือกต่อชุดสอบ (เห็นทันทีหลังส่ง / ไม่เห็น / เห็นหลังครูประกาศ)
- **กันลอก (เปิด/ปิดต่อชุดสอบ):** สลับลำดับข้อ, สลับตัวเลือก, สุ่ม N ข้อจากคลัง, ทำทีละข้อห้ามย้อน
- **สิทธิ์:** ครูสร้าง/แก้ชุดสอบของตัวเองและแชร์ให้ครูอื่นได้ · Admin เห็นทุกชุด
- **การสอบชนะ Staff session และสวิตช์ปิดการบังคับใช้ทั้งระบบ** ออกได้ด้วยการจบรอบสอบ, เอาเครื่องออกจากรอบสอบ หรือรหัสฉุกเฉินเท่านั้น
- **Server ล่ม + เครื่องรีบูต:** กลับเป็นกฎปกติ (disk freeze ทำให้จำสถานะไม่ได้) และแสดงเหตุการณ์ในหน้าคุมสอบ/รายงาน
- **หมดเวลา:** ล็อกจอ "หมดเวลา" + เก็บไฟล์อัตโนมัติ (ถ้าเปิดโมดูลเครื่องมือสอน) จนครูจบรอบสอบ
- **ฝั่งครู = หน้าใน Console** (ไม่ทำโปรแกรมแยก) · **OnlineConsole = คุมสอบ + ดูผลเท่านั้น** สร้างโจทย์และตรวจอัตนัยทำใน Console
- **โมดูลที่พึ่งกัน:** Exam ใช้ Website ได้ถ้าชุดสอบอนุญาตบางเว็บ · ใช้ Sign-in และเครื่องมือสอนเมื่อเปิดอยู่ ถ้าปิดก็ยังสอบได้ (ไม่มีแบบบังคับล็อกอิน / ไม่มีเก็บไฟล์)
- แนวคิดบางส่วนได้จากการดูโปรแกรมสอบเชิงพาณิชย์ที่โรงเรียนมี **ใช้แค่แนวคิด ห้าม decompile/แกะ protocol/คัดลอกหน้าตาหรือข้อความ**

### จุดที่ต้องระวัง
- **ห้ามรื้อสิ่งที่ pilot รอบ 1 กำลังทดสอบโดยไม่จำเป็น:** M0 ต้องไม่เปลี่ยนพฤติกรรมที่ผู้ใช้เห็น (refactor + สวิตช์โมดูลที่ค่าเริ่มต้นเปิดทุกตัว)

## ข้อมูลอ้างอิงในโค้ด (ณ 30 ต.ค. 2569)

- **Endpoint ของ Server:** อยู่ใน `Server/Endpoints/<Group>Endpoints.cs` 14 กลุ่ม (หลัง WP0) · Program.cs เหลือแค่ตั้งค่า + `app.MapXxxEndpoints()` · `MapCommandEndpoints(eventCommandLifetime)` รับพารามิเตอร์เพิ่ม · DTO อยู่ใน `Endpoints/EndpointRequests.cs`
- **Auth ของ Console:** header `X-Auth-Token` ตรวจที่ `GetAuthorizedAdmin` ใน `Server/Endpoints/AuthHelpers.cs` · token อยู่ในตาราง `AuthTokens` · `PasswordHasher` = PBKDF2 · มี `LoginThrottle` อยู่แล้ว
- **Agent loopback API:** ผูกไว้ที่ `127.0.0.1:8788` ใน `Agent/Program.cs` (`/bypass/set` อยู่ราวบรรทัด 200)
- **Failover:** `Agent/Worker.cs` (`FailuresBeforeFallback = 5`, `SuccessesBeforeRecovery = 7`) · `ServerClient.SwitchTo()`
- **Console:** `DashboardWindow.xaml` คือหน้าหลักแบบแท็บ + sidebar (ราว 1,079 บรรทัด) · ธีมอยู่ใน `Console/Theme/`
- **ปัญหาที่รู้อยู่:** ดู "Known limitations" ใน `docs/architecture.md`
