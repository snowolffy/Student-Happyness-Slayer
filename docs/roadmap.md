# Roadmap: ไปสู่ระบบคุมห้องคอมแบบเต็ม (เมมกลาง)

> **ไฟล์นี้คือ "เมมกลาง"** ของงานรอบนี้ เก็บการตัดสินใจทั้งหมดที่คุยกับผู้ใช้แล้ว (29–30 ต.ค. 2569)
> และแบ่งงานขั้น 1 เป็น work package (WP) ให้ orchestrator แจกให้ worker ทำขนานกันได้
> กฎการทำงานร่วมกันอยู่ใน [`CLAUDE.md`](../CLAUDE.md)
>
> **Wireframe (แหล่งอ้างอิงหน้าตา):** https://claude.ai/artifact/7KbHzR3PrVq8r5upXrrJoW
> canvas เป็นของส่วนตัวผู้ใช้ worker จึงเปิดไม่ได้ **ต้นฉบับทุกหน้าสำเนาไว้แล้วที่ [`docs/wireframes/`](wireframes/README.md)** ให้อ่านหน้าที่เกี่ยวข้องก่อนทำงาน UI

## การตัดสินใจทั้งหมด (ยืนยันกับผู้ใช้แล้ว)

### Sign-in และบัญชี
- **บัญชีนักเรียน:** ล็อกอินด้วยเมลโรงเรียนหรือรหัสนักเรียน + รหัสผ่าน โดย Admin เป็นคนจัดการบัญชี **เป้าหมายคือ log รายบุคคล**
  - ไม่สร้างบัญชี Windows ให้นักเรียน (ชนกับ disk freeze) ล็อกอินที่ระดับแอปบนจอล็อกของ AgentTray แทน
- **Roster Manager** เป็นโปรแกรมแยก (WPF) แต่ใช้ Server และ DB ตัวเดียวกัน
  - **ข้อมูลนำเข้า:** CSV จับคู่คอลัมน์ได้ · รหัสนักเรียนซ้ำกับของเดิม = อัปเดตชื่อและห้องโดยไม่แตะรหัสผ่าน
  - **รหัสเริ่มต้น:** สุ่ม 6 หลักต่อคน + บังคับเปลี่ยนตอนล็อกอินครั้งแรก · พิมพ์ใบแจกได้ A4 ละ 10 ใบ · เก็บแบบ hash ย้อนดูไม่ได้
  - **เลื่อนชั้นปี:** ทำปีละครั้ง นักเรียนที่จบปิดบัญชีได้ และสำรอง DB ให้อัตโนมัติก่อนเลื่อน
- **การบังคับล็อกอินเปิด/ปิดได้ที่ตั้งค่า Server** (ทั้งระบบหรือเลือกห้อง)
  - เปิดอยู่: ไม่ล็อกอิน = ใช้เครื่องไม่ได้
  - ปิด: เครื่องที่ค้างอยู่หน้าล็อกอินจะปลดเองภายใน 1 รอบ poll
  - สลับไปเปิด: ไม่เตะคนที่ใช้เครื่องอยู่ออกกลางคัน
- **ความปลอดภัยบัญชี:** ล็อกบัญชีเมื่อกรอกผิด 5 ครั้ง (ครูปลดได้) · รหัสขั้นต่ำ 6 ตัว · Teacher รีเซ็ตรหัสนักเรียนได้ (ปิดสิทธิ์ได้) · บัญชีเดียวล็อกอินเครื่องใหม่ = เตะเครื่องเก่าออก (ค่าเริ่มต้น) + บันทึก log
- **logout อัตโนมัติ:** เมื่อไม่ได้ใช้งาน N นาที (ค่าเริ่มต้น 15) และเมื่อปิด/รีสตาร์ทเครื่อง มีปุ่ม "ไม่ใช่ฉัน" ในเมนู tray
- **ไม่มีตาราง/คาบเรียน** เพราะวิชาอื่นขอยืมห้องและครูพานักเรียนเข้าคาบว่างบ่อย ห้องอยู่โหมดใช้งานทั่วไปเสมอ
  - รายงาน = "ประวัติการใช้เครื่อง" กรองตามช่วงเวลา ห้องคอม และห้องเรียนของนักเรียน ใช้ดูประกอบเท่านั้น ไม่ใช่ใบเช็คชื่อทางการ
- **Role มี 2 ระดับ**
  - **Admin:** ทำได้ทุกอย่าง
  - **Teacher:** คุมห้อง ดูจอ เปิดโหมดสอบ รีเซ็ตรหัสนักเรียน (ถ้าเปิดสิทธิ์) และเปิด Staff session ได้ แต่แก้กฎถาวร ผู้ใช้ ห้อง และตั้งค่าระบบไม่ได้
- **ชื่อที่แสดง (display name)** สำหรับบัญชี Admin/Teacher
  - ใช้แสดงทุกที่ที่คนเห็น เช่น "Staff session (ครูสมชาย)", "ล็อกโดย ครูสมชาย", ผู้ส่งข้อความ, แถบล่าง Console
  - เจ้าของบัญชีแก้เองได้ Admin แก้ให้ได้ · username ใช้ล็อกอินและแก้ไม่ได้
  - **Audit Log เก็บทั้ง username และชื่อที่แสดง ณ ตอนนั้น**
- **Staff session:** ครูล็อกอินที่เครื่องนักเรียนด้วยบัญชี Console
  - ปิดกฎทั้งเครื่องชั่วคราว: ค่าเริ่มต้น 30 นาที สูงสุด 120 นาที ต่อเวลาได้ จบเองเมื่อหมดเวลาหรือรีบูต
  - บันทึกเหมือนตอน admin ล็อกอิน Console (บัญชี + เครื่อง) และไม่นับเป็นการใช้เครื่องของนักเรียน
  - **ใช้กลไก token จาก Server แบบเดียวกับที่ใช้แทน `bypass/set`** (ดู WP2)
- **รหัสฉุกเฉิน (Server ล่ม):** ใช้ TOTP มาตรฐาน 6 หลัก เปลี่ยนทุก 30 วินาที secret ฝังมาตอนติดตั้ง Agent
  - ครูดูรหัสได้ 2 ทาง: แอป Authenticator หรือหน้าเว็บ Google Apps Script (จำกัดให้เปิดได้เฉพาะบัญชีครู และบันทึกว่าใครเปิดดู) · secret ของ Apps Script เก็บใน Script Properties
  - ปลดเครื่องได้แบบไม่ระบุชื่อ แล้วบันทึกย้อนหลังเมื่อ Server กลับมา
  - **ห้ามใช้ OnlineConsole แสดงรหัส** เพราะรันบนเครื่อง Server จึงล่มไปพร้อมกัน

### เครือข่ายและความปลอดภัย
- **HTTPS ด้วย self-signed certificate:** MSI ติดตั้งใบรับรองให้เครื่องนักเรียนเชื่อถือ **ต้องเสร็จก่อนเริ่มเก็บรหัสผ่านนักเรียน** · ช่วงย้ายระบบมีตัวเลือก "ยอมรับ HTTP เดิม"
- **Agent ตอนบูต: แข่งกันระหว่าง LAN กับ Tailscale โดยให้ LAN เป็นหลัก**
  - ยิง LAN ก่อน ถ้าไม่ตอบใน 2 วินาที ยิง Tailscale ตามไปด้วย ทางไหนตอบก่อนใช้ทางนั้น
  - ถ้าได้ Tailscale ให้ probe LAN อยู่เบื้องหลัง พอ LAN ติดค่อยสลับกลับ
  - หลังบูตแล้วใช้กติกาเดิม (เสีย 5 ครั้งสลับไป / ดี 7 ครั้งสลับกลับ ใน `Worker.cs`)

### จอนักเรียน (AgentTray)
- **แนวทางการ** · ข้อความบนจอล็อกแก้ได้ (ค่าเริ่มต้นในตั้งค่า + ครูพิมพ์ทับเฉพาะครั้งตอนกดล็อก)
- **หน้าล็อกอิน:** การ์ดแบ่งสองฝั่ง ซ้ายเป็นภาพจาก `Assets\LoginHero.png` (ฝังมากับ MSI ตอนนี้ใช้ placeholder) ขวาเป็นฟอร์ม
  - การ์ดลอยมีเงา พื้นหลังเป็นสีพื้นเดิมโรย **จุดเรียงแบบตาราง**
  - **มีปุ่มปิดเครื่อง/รีสตาร์ทที่มุมขวาล่าง ใครก็กดได้** · จอที่ครูสั่งล็อกห้ามมีปุ่มนี้
- **ระหว่างใช้งานห้ามมีแถบลอยด้านบน** เพราะทับแท็บเบราว์เซอร์
  - โหมดปกติ: เด้งแจ้งชื่อ 5 วินาที + เมนูที่ไอคอน tray
  - โหมดสอบ / Staff session: ป้ายเล็กมุมขวาล่าง ซ่อนไม่ได้
- **สถานะผิดพลาดของจอล็อกอิน:** รหัสผิด (ไม่บอกว่าผิดช่องไหน) · บัญชีถูกล็อก · บัญชีใช้อยู่ที่เครื่องอื่น · บังคับตั้งรหัสใหม่

### Console (WPF): โครงใหม่
- **ทุกอย่างเป็นหน้าใน sidebar แบบจัดกลุ่ม** ไม่ใช้หน้าต่างลอยแล้ว
  - ห้องเรียน: Clients, ผังที่นั่ง, Live View, โหมดสอบ
  - กฎ: กฎโปรแกรม, Program Review, Website Control
  - บันทึก: Logs/Audit, ประวัติการใช้เครื่อง
  - ระบบ: ผู้ใช้, ห้อง, ตั้งค่า
- **Toast มุมขวาล่าง** แทนข้อความที่แทรกในหน้า
  - สำเร็จ/ข้อมูลหายเองใน 4 วินาที · error ค้างจนกดปิด
  - ซ้อนกันสูงสุด 3 อัน · ถ้าแผงข้างเปิดอยู่ ให้ขยับหลบ
  - ใช้กับ: ล็อกอินสำเร็จ, ผลคำสั่ง (มีลิงก์ "ดูผล"), error, ข้อมูลทั่วไป
- **แผงข้อมูลเครื่อง (inspector) สไลด์จากขวา ทับอยู่บน grid** ไม่ดันคอลัมน์
  - หุบเหลือแถบแคบได้ · Esc หรือ ✕ ปิด
  - เลือกหลายเครื่อง = แผงเปลี่ยนเป็นคำสั่งแบบกลุ่ม
- **ประกาศสถานะของทั้งระบบอยู่ในแถบหัวของหน้า** เช่น ปิดการบังคับใช้ทั้งระบบ, โหมดสอบกำลังทำงาน, Server กำลังเชื่อมต่อใหม่
  - แถบหัวสูงเท่าเดิมเสมอ เปลี่ยนแค่สี และมีปุ่มแก้ในตัว · ขึ้นทุกหน้า
  - หลายเรื่องพร้อมกัน = แสดงเรื่องที่ร้ายแรงที่สุด + ป้าย "+N"
- **หน้าล็อกอิน Console:** เปิดเป็นหน้าต่างขนาด Console ปกติ ไม่ใช่หน้าต่างเล็ก
  - ตรงกลางเป็นการ์ดแบ่งสองฝั่ง: ภาพ `Assets\LoginHero.png` + ฟอร์ม (Server IP, Port, Username, Password)
  - พื้นหลังจุดเรียงแบบตาราง

**ลำดับ:** WP3-1 ต้องเสร็จก่อน (มี model, API และ migration ทั้งหมด) จากนั้น WP3-2 ถึง WP3-5 ทำขนานกันได้ และไม่มี migration เพิ่ม ถ้าจำเป็นต้องสร้าง ให้ทำทีละตัวตามลำดับที่ merge

### WP3-1: Server ของ Sign-in ทั้งหมด (migration)
- **Model:**
  - `Student`: รหัสนักเรียน (unique), ชื่อ-สกุล, เมลโรงเรียน (unique nullable), ห้องเรียน (string เช่น "ม.2/3"), password hash, `MustChangePassword`, จำนวนครั้งที่กรอกผิด, `LockedUntil` หรือ `IsLocked`, `IsDisabled`
  - `StudentSession`: นักเรียน, เครื่อง, เวลาเริ่ม/จบ, วิธีจบ (กดออก / ไม่ได้ใช้งาน / ปิดเครื่อง / ครูสั่ง / ไม่ใช่ฉัน / ถูกเตะเพราะล็อกอินที่อื่น)
  - ตารางตั้งค่า Sign-in ตาม wireframe `nf-signin-settings`
- **API สำหรับ Agent/AgentTray:** login นักเรียน (รองรับทั้งรหัสนักเรียนและเมล), logout, เปลี่ยนรหัสครั้งแรก
  - ตอบเป็นรหัสสถานะที่ชัดเจน ได้แก่ ผิด / ล็อก / ใช้อยู่ที่เครื่องอื่น / ต้องเปลี่ยนรหัส
  - ใช้กติกา "บัญชีเดียวหลายเครื่อง" ตามค่าที่ตั้งไว้
- **API สำหรับ Roster:** CRUD, นำเข้า CSV (dry-run + commit), สร้างรหัสเริ่มต้น (สุ่ม 6 หลัก แสดงได้ครั้งเดียว), รีเซ็ตรหัส, ปลดล็อก, ย้ายห้องเรียน, เลื่อนชั้น (สำรอง DB อัตโนมัติก่อนเลื่อน)
  - สิทธิ์: Admin เท่านั้น ยกเว้นรีเซ็ตรหัสและปลดล็อก ที่ Teacher ทำได้ถ้าเปิดสิทธิ์ไว้
- **API สำหรับ Console:** นักเรียนที่ใช้เครื่องอยู่ (ใส่ใน clients list), ประวัติการใช้เครื่อง (กรองช่วงเวลา, ห้องคอม, ห้องเรียน), สั่ง logout นักเรียน
- **อื่นๆ:**
  - poll ส่งค่า "ต้องล็อกอินไหม" ไปให้ Agent
  - log ทุกอย่างที่เกิดระหว่าง session ให้ผูกกับนักเรียน
  - บริการสำรอง DB ตามตั้งค่า `nf-settings-more`
- **เกณฑ์เสร็จ:** ทดสอบผ่าน API ครบทุกสถานะ · migration บน DB เก่าไม่พัง

### WP3-2: Roster Manager (โปรเจกต์ WPF ใหม่)
- **ไฟล์:** `src/OnionProcOparetor.RosterManager/` (ใหม่) + เพิ่มเข้า solution + เพิ่มเป็น feature ใหม่ (ไม่ติ๊กเป็นค่าเริ่มต้น) ใน `installer/OnionProcOparetor.ServerConsole.wxs`
- **งาน:** ทุกหน้าตาม wireframe `nf-roster-login`, `nf-roster`, `nf-import`, `nf-password`, `nf-print`, `nf-promote`
  - ใช้ theme token ชุดเดียวกับ Console ให้คัดลอกโฟลเดอร์ Theme มา เพราะ repo นี้ไม่มี shared library
  - ใช้ toast และแถบประกาศแบบเดียวกับ Console
  - ใบรหัสผ่านพิมพ์ได้และบันทึกเป็น PDF ได้

### WP3-3: จอนักเรียน (AgentTray + Agent)
- **งาน:** ตาม wireframe `st-login`, `st-login-states`, `st-session`, `st-staff-start`, `st-locked`
  - **จอล็อกอิน:** การ์ดลอย, ภาพ `Assets\LoginHero.png` ฝังมากับ MSI, พื้นจุดเรียงตาราง, ปุ่มปิดเครื่อง/รีสตาร์ทมุมขวาล่าง
  - **ระหว่างใช้งาน:** แจ้งชื่อ 5 วินาที + เมนู tray ("ไม่ใช่ฉัน" / ออกจากระบบ) · ออกจากระบบเองเมื่อไม่ได้ใช้งาน
  - **Staff session:** ใช้ API ของ WP2 · ป้ายมุมขวาล่าง
  - **จอที่ครูล็อก:** พื้นสีดำ แนวทางการ ข้อความแก้ได้ (ค่าเริ่มต้น + ทับเฉพาะครั้ง) **ห้ามมีปุ่มปิดเครื่อง**
  - Agent บังคับให้ต้องล็อกอินก่อนเมื่อ Server สั่ง และแนบนักเรียนปัจจุบันไปกับ poll และ log
- **ทดสอบ:** ทำส่วน UI ด้วยโหมด preview + จับภาพ · Agent รันจริงบนเครื่องนี้ไม่ได้ ให้ระบุไว้

### WP3-4: รหัสฉุกเฉิน (TOTP)
- **งาน:**
  - secret ฝังตอนติดตั้ง Agent ผ่าน MSI property หรือไฟล์ที่ MSI วางไว้
  - Agent ตรวจ TOTP ได้เองโดยไม่ต้องใช้ Server (RFC 6238 ยอมคลาดเคลื่อน ±1 ช่วง)
  - AgentTray: จอ `st-emergency` ขึ้นเมื่อติดต่อ Server ไม่ได้
  - บันทึกการใช้รหัสฉุกเฉินไว้ แล้วส่งขึ้น Server ตอนกลับมาออนไลน์
  - Console: หน้าตั้งค่ารหัสฉุกเฉิน (แสดง QR และ key, ทดสอบรหัส, เปลี่ยน secret)
  - เพิ่มไฟล์ `docs/apps-script/emergency-code.gs` พร้อมวิธีติดตั้ง: หน้าเว็บ Apps Script แสดงรหัส จำกัดให้เปิดได้เฉพาะบัญชีที่กำหนด บันทึกว่าใครเปิดดู และเก็บ secret ใน Script Properties
- **เกณฑ์เสร็จ:** รหัสจาก Authenticator และจาก Apps Script (คำนวณด้วยสูตรเดียวกัน) ตรวจผ่านในตัวทดสอบ

### WP3-5: Console ส่วน Sign-in
- **งาน:**
  - **หน้าตั้งค่าแบบ 2 คอลัมน์:** "Console เครื่องนี้" / "ทั้งระบบ" รวมหน้า Sign-in, Staff session, รหัสฉุกเฉิน (หน้าจาก WP3-4), HTTPS (ข้อมูลใบรับรอง) และสำรองข้อมูล
  - **Logs + Audit** รวมเป็นหน้าเดียว 2 แท็บ
  - **หน้าประวัติการใช้เครื่อง** ตาม wireframe `nf-attendance`
  - **หน้า Clients:** เพิ่มคอลัมน์นักเรียน + การ์ด "ล็อกอินแล้ว" + ปุ่ม "บังคับ logout" ใน inspector
  - **หน้าต่างล็อกจอ** พิมพ์ข้อความทับได้
  - **OnlineConsole:** คอลัมน์นักเรียน + หน้าประวัติการใช้เครื่องบนมือถือ

## ขั้น 4: เครื่องมือสอน · work packages
อ้างอิง wireframe: `tc-openurl`, `tc-raisehand`, `tc-files`, `tc-broadcast`, `tc-broadcast-student`

**ลำดับ:** รอบแรก WP4-1 + WP4-2 ทำขนานกัน · รอบสอง WP4-3 + WP4-4 · **ลำดับ migration:** WP4-1 → WP4-3 (ต่อจาก `AddEmergencyCode`)
**ส่งคำสั่งไปเครื่องนักเรียน:** ใช้ช่องทางเดิม (Command queue → Agent `CommandProcessor` → pipe → AgentTray) เพิ่ม command type ใหม่ ห้ามสร้างช่องทางใหม่ ยกเว้น WP4-4 ที่ต้องส่งภาพต่อเนื่อง
**จุดชนที่รู้ล่วงหน้า:** `Agent/Services/CommandProcessor.cs`, `AgentTray/App.xaml.cs`, `Console/DashboardWindow.xaml(.cs)` แก้ได้แบบเพิ่มเท่านั้น (case ใหม่, ปุ่มใหม่) ไม่จัดโครงเดิม

### WP4-1: เปิด URL / โปรแกรมทั้งห้อง (migration)
- **Server:** ตาราง `LaunchableProgram` (ชื่อ, path, arguments) Admin ตั้งได้ · endpoint สั่งเปิด URL หรือโปรแกรมกับทั้งห้องหรือเครื่องที่เลือก (Teacher ใช้ได้) · โปรแกรมต้องเลือกจากรายการเท่านั้น ห้ามรับ path อิสระจาก Teacher
- **Agent:** command `OpenUrl` (เฉพาะ http/https) และ `LaunchProgram` (ตรวจซ้ำกับรายการจาก Server) เปิดใน session ของผู้ใช้ผ่าน `UserSessionLauncher`
- **Console:** dialog ตาม `tc-openurl` เปิดจากแถบ Clients · หน้าตั้งค่ารายการโปรแกรม (Admin) · **OnlineConsole:** หน้าเปิด URL บนมือถือ
- **เกณฑ์เสร็จ:** ทดสอบ API กับ Server ทดลอง · Agent ปฏิเสธ URL ที่ไม่ใช่ http/https และโปรแกรมนอกรายการ (unit test)

### WP4-2: ยกมือ (ไม่มี migration)
- **AgentTray:** ปุ่มยกมือ (ตามตำแหน่งใน `tc-raisehand`) กดซ้ำได้หลัง 1 นาที · ส่งผ่าน Agent loopback → Server
- **Server:** คิวยกมือเก็บในหน่วยความจำ (หายเมื่อรีสตาร์ต Server ยอมรับได้) ผูกชื่อนักเรียนจาก session ปัจจุบัน · push ผ่าน SignalR ไป Console · ครูกดรับ/ล้างคิว
- **Console:** แผงคิวยกมือ + toast เมื่อมีคนยกมือ + ไฮไลต์เครื่องใน grid · **OnlineConsole:** แสดงคิว
- **เกณฑ์เสร็จ:** API + cooldown ทดสอบจริง · ภาพหน้าจอ Console (สว่าง/มืด) และปุ่มบน AgentTray

### WP4-3: แจก / เก็บไฟล์ (migration)
- **Server:** เก็บไฟล์ที่ครูแจกไว้ในโฟลเดอร์ข้อมูลของ Server (จำกัดขนาดต่อไฟล์ ตั้งค่าได้) · งานเก็บไฟล์ (ชื่องาน, เป้าหมาย, เวลาปิดรับ) · ไฟล์ที่เก็บได้แยกโฟลเดอร์ตามชื่อนักเรียนจากการล็อกอิน (ถ้าไม่ได้ล็อกอินใช้ชื่อเครื่อง)
- **Agent:** command ดาวน์โหลดไฟล์ไปไว้ใน Desktop ของผู้ใช้ (โฟลเดอร์ "ไฟล์จากครู") · เก็บไฟล์: AgentTray ให้นักเรียนเลือกไฟล์ส่ง แล้วอัปโหลดผ่าน Agent
- **Console:** หน้าตาม `tc-files` (แจก / เก็บ / ดูสถานะรายเครื่อง / เปิดโฟลเดอร์ที่เก็บได้)
- **เกณฑ์เสร็จ:** อัปโหลด/ดาวน์โหลดผ่าน API จริงกับ Server ทดลอง (ตั้ง storage path ไป temp) · ตรวจชื่อไฟล์กัน path traversal

### WP4-4: ส่งจอครู (ไม่มี migration)
- **Console:** จับจอครู 5–10 fps เป็น JPEG ย่อขนาด ส่งขึ้น Server · แถบแดงเตือนบนจอครูตลอดที่ส่ง (`tc-broadcast`) · หยุดได้ทันที
- **Server:** relay เฟรมล่าสุดผ่าน SignalR (ไม่เก็บลงดิสก์ ทิ้งเฟรมเก่าถ้าผู้รับช้า)
- **Agent/AgentTray:** command เริ่ม/หยุด · AgentTray แสดงเต็มจอตาม `tc-broadcast-student` (ล็อกจอระหว่างดู หรือเป็นหน้าต่างก็ได้ตามที่ครูเลือก) · Agent ดึงเฟรมจาก Server ส่งต่อให้ tray
- **เกณฑ์เสร็จ:** ส่งเฟรมจาก Console ทดลองผ่าน Server ทดลอง ไปถึงตัวรับทดลองได้ วัด fps และขนาดเฟรมจริง · ภาพหน้าจอแถบแดงและจอนักเรียน

## คำขอเพิ่มจากผู้ใช้ (3 พ.ย. 2569) · ยังไม่เริ่ม
- **WP4-4 ส่งจอครู (แก้ก่อนทำต่อ):** แถบ "กำลังส่งจอ" คงแบบเดิมแต่ให้**เล็กลงและหุบเก็บได้** · ระหว่างส่งให้มี**กรอบแดงรอบจอครู**ตลอด เพื่อให้รู้ว่ายังส่งอยู่แม้หุบแถบไปแล้ว
  - **กรอบแดง (ตัดสินแล้ว 3 พ.ย.):** หนา 3–4px ไม่กะพริบ กดทะลุได้ (click-through) **แสดงเฉพาะบนเครื่องครู ห้ามติดไปในภาพที่ส่งให้นักเรียน** (ตัดออกจากภาพที่จับ เช่น ใช้ `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` กับหน้าต่างกรอบและแถบ)
  - **เขียนบนจอ (ตัดสินแล้ว 3 พ.ย.):** แผ่นใสทับจอครู ปากกา 3–4 สี, ไฮไลต์, ยางลบ, ล้างทั้งหมด · สลับโหมดเขียน/ใช้เมาส์ปกติด้วยปุ่มบนแถบหรือ Ctrl+Shift+D · เส้นที่เขียน**ติดไปในภาพที่ส่ง** (ต่างจากกรอบแดงและแถบ)
  - **Zoom (ตัดสินแล้ว):** ครูเป็นคนซูมแบบแว่นขยาย นักเรียนเห็นภาพที่ซูมตามครู · นักเรียนซูมเองไม่ได้
  - **แถบตอนหุบ (ตัดสินแล้ว):** เหลือปุ่มกลมแดงเล็กลากย้ายได้ กดแล้วกางกลับเป็นแถบเต็ม (หยุดส่ง, เครื่องมือเขียน, zoom)
  - **ทำต่อจาก `feat/p4-wp4` (`0ae0ec7`):** ปรับ BroadcastWarningBarWindow ให้เล็ก/หุบได้ + เพิ่มหน้าต่างกรอบแดง + แผ่นใสเขียน + แว่นขยาย
- **UI-1 AgentTray/Agent ใช้แนวทางเดียวกับ Console:** ใช้ theme token, style, ไอคอน และ control ชุดเดียวกับ Console ทุกหน้าต่างของ AgentTray (จอล็อกอิน, จอล็อก, ยกมือ, staff session, รหัสฉุกเฉิน, ป้ายต่างๆ) · แนวทางที่เสนอ: แยก theme/control ของ Console ออกเป็นโปรเจกต์ไลบรารีร่วม (เช่น `OnionProcOparetor.UI`) ให้ Console, AgentTray และ RosterManager อ้างอิงร่วมกัน
- **UI-2 ล็อกอิน Console เป็นหน้าต่างเดียวกับโปรแกรม:** ล็อกอินเสร็จแสดงตัวหมุนโหลดสั้นๆ แล้ว fade เข้าหน้าหลักในหน้าต่างเดิม (ไม่เปิดหน้าต่างใหม่)
- **UI-3 หน้าย่อยอยู่ในหน้าต่างหลัก (ผู้ใช้เห็นด้วย 3 พ.ย.):** แบ่ง 30 หน้าต่างของ Console เป็น 3 กลุ่ม
  - **แผงสไลด์ขวา (inspector เดิม):** ของเครื่องเดียว เช่น ตั้งค่าเครื่อง, โปรแกรมที่เปิดอยู่, คำสั่งค้าง, ยกเว้นกฎ

## ข้อมูลอ้างอิงในโค้ด (ณ 30 ต.ค. 2569)

- **Endpoint ของ Server:** อยู่ใน `Server/Endpoints/<Group>Endpoints.cs` 14 กลุ่ม (หลัง WP0) · Program.cs เหลือแค่ตั้งค่า + `app.MapXxxEndpoints()` · `MapCommandEndpoints(eventCommandLifetime)` รับพารามิเตอร์เพิ่ม · DTO อยู่ใน `Endpoints/EndpointRequests.cs`
- **Auth ของ Console:** header `X-Auth-Token` ตรวจที่ `GetAuthorizedAdmin` ใน `Server/Endpoints/AuthHelpers.cs` · token อยู่ในตาราง `AuthTokens` · `PasswordHasher` = PBKDF2 · มี `LoginThrottle` อยู่แล้ว
- **Agent loopback API:** ผูกไว้ที่ `127.0.0.1:8788` ใน `Agent/Program.cs` (`/bypass/set` อยู่ราวบรรทัด 200)
- **Failover:** `Agent/Worker.cs` (`FailuresBeforeFallback = 5`, `SuccessesBeforeRecovery = 7`) · `ServerClient.SwitchTo()`
- **Console:** `DashboardWindow.xaml` คือหน้าหลักแบบแท็บ + sidebar (ราว 1,079 บรรทัด) · ธีมอยู่ใน `Console/Theme/`
- **ปัญหาที่รู้อยู่:** ดู "Known limitations" ใน `docs/architecture.md`
